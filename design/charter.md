# eharness 헌장 (charter)

> eharness = 한 머신의 모든 Claude Code 세션을 다루는 개인용 하네스 우산.
> 이 문서는 **바뀌지 않는 원칙만 담는 정본(SSOT)** 이다. 이름·경로·폴더 구조·로드맵·외부 링크 같은
> 가변 바인딩은 여기 두지 않는다 — 그것들의 정본은 §4의 문서 체계를 따른다.

## 1. 역할 경계

| 역할 | 담당 | 경계 규칙 |
|---|---|---|
| **관측면** | 세션·터미널을 밖에서 읽어 상태를 만든다 | **읽기 전용.** 예외 쓰기는 해당 능력 스펙의 what에 선언된 것만. 어떤 경우에도 차단·판단하지 않는다 |
| **제어면** | 세션에 배선되는 자산(스킬·훅·에이전트·도구) | 채택 게이트를 통과한 능력만 존재. 자산마다 capability 태그. 전역 설정 반영은 배선기로만 |
| **외부 자산** | 이미 다른 도구가 담당하는 능력 | 재발명 금지. 무엇이 외부 자산인지는 map이 정본 |

새 능력은 반드시 위 중 하나에 소속되며, 소속을 한 문장으로 말할 수 없으면 **보류**.

## 2. 채택 게이트 (5종 전부 통과해야 착수)

1. **증거** — 최근 2주 내 같은 수동 작업·실패 2회 이상. 소스는 관측면의 이벤트 버스.
2. **자산** — 기존 자산·설정 변경으로는 해결 불가한가.
3. **경계** — §1의 소속을 한 문장으로 말할 수 있는가.
4. **되돌림** — 배선기 한 방 제거가 설계에 포함됐는가.
5. **선언** — 6하(what·when·where·who 포함)를 전부 채웠는가.

판정과 근거는 decisions에 한 줄씩 append. **통과 기록이 먼저 있어야 구현 착수.**

## 3. 운영 규칙

- **폴더 선행 생성 금지** — 구조는 첫 채택 능력이 요구할 때 만든다. 빈 폴더는 할 일 목록으로 역전된다.
- **capability 태그** — 제어면 자산 frontmatter에 소속 능력 필수. 능력 단위 설치/제거의 단위.
- **리포 = 소스, 전역 설정 = 빌드 산출물** — 전역 설정 직접 편집 금지, 배선기로만(멱등·백업·되돌림).
- **모델 세대 변경 = 전 능력 재검증 트리거** — 하네스의 모든 요소는 "모델이 스스로 못하는 것"에 대한
  가정의 인코딩이다. 모델 세대가 바뀌면 능력별로 가정이 아직 유효한지 재판정하고, 무효화된 능력은
  되돌린다(채택 게이트의 감가 방향 — 늘리는 게이트와 같은 무게로 줄이는 게이트를 적용).

## 4. 구성 요소 설계 기준 (유형별 불변 원칙)

제어면 자산을 만들 때 유형별로 지키는 기준. 유형의 제품명·바인딩은 map이 정본.

| 유형 | 기준 |
|---|---|
| **지침** (상시 로드 문서·스킬 본문) | 적정 고도 — 취약한 하드코딩도, 망라적 규칙도 금지. 정준적 예시 소수. 프루닝 기준: **"이 줄을 지우면 에이전트가 실수하는가"** — 아니면 지운다 |
| **상시 vs 온디맨드** | 컨텍스트는 유한한 주의 예산 — 매 세션 필요한 지식만 상시 로드, 특정 작업용 지식은 온디맨드(스킬)로 분리 |
| **훅** | 매번 예외 없이 일어나야 하는 **결정론적 행동만** 훅으로, 권고는 지침으로. 관측면 훅은 §1 규칙(무개입) |
| **도구** | 에이전트의 최우선 행동 수단 — 도구로 풀 수 있는 것을 지침 문장으로 우회하지 않는다. 외부 서비스 통합은 표준 프로토콜(MCP)로 |
| **서브에이전트** | 목적은 병렬화가 아니라 **컨텍스트 격리** — 반환은 요약으로. 병렬 서브에이전트 간 결정 충돌(연속성 훼손) 주의 |
| **검증** | **실행 가능한 체크가 없으면 사람(또는 모델 자기 보고)이 검증 루프가 된다** — 모든 능력 스펙의 verify는 실행 가능해야 하며, 작업자와 평가자를 분리할 수 있으면 분리한다 |
| **권한** | 능력의 who 선언은 최소 권한으로 — 무인 실행 경로일수록 도구 스코프를 좁힌다 |

## 5. 문서 체계 (무엇이 어디의 정본인가)

| 문서 | 정본 범위 | 가변성 |
|---|---|---|
| charter | 원칙·게이트·규칙 | 불변 — 개정 자체가 decisions에 기록될 사건 |
| map | 능력 목록·판정 상태·이름/폴더 바인딩·목표 형상·로드맵·외부 자산 목록 | 가변 |
| decisions | 판정·개정 이력 | append-only |
| specs/<능력> | 능력별 6하 선언·구체 경로·되돌림 절차 | 능력과 함께 개정 |

설계 배경·다이어그램은 외부 설계 문서에 있을 수 있으나 **정본이 아니다** — 충돌 시 이 체계가 이긴다.
