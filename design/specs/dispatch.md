# dispatch (리더 → 자식 지시 분배) 스펙

> 리더 세션이 등록된 자식 세션들에게 서로 다른 지시를 병렬로 내리고, 완료 회신을 받는 규약.
> 예: "자식1은 기획, 자식2는 리뷰". 2026-09-04.

```yaml
capability: dispatch
why:    decisions.md#2026-09-04-게이트-통과-dispatch   # 병렬 세션 조율 수동 반복
what:   없음                                          # 무상태 — 계층(comm 소유)을 읽고 메시지를 보낼 뿐
how:    [skill:cctv-dispatch]                         # 전송은 리더 세션 자신의 SendMessage
when:   [on-demand]                                   # 사용자가 분배 지시를 내릴 때
where:  global
who:    리더 세션만(children 등록 필수 — 없으면 발송 중단·등록 안내) · 사용자 지시 기반
        # 임의 작업 생성·브로드캐스트·미등록 대상 발송 금지. 용어: 자식=팀원(동일 대상 병기)
```

## 문제
자식 세션 여럿에 일을 나눠 줄 때 사람이 터미널을 옮겨 다니며 각각 프롬프트를 쳐야 한다.
계층(리더/자식)은 이미 관제에 등록돼 있는데 지시 전달이 그걸 활용하지 못한다.

## 최소 설계
스킬 `cctv-dispatch` 하나(지침 전용):
1. 자식(팀원) 확인 — `register.sh status`(comm)의 children으로 이름 해석. **비어 있으면 발송하지 않고
   중단** — "리더가 아님 · register.sh child <이름>으로 등록" 안내만 (계층이 곧 권한).
2. 분배 — 자식별로 SendMessage 1건: `[리더 지시]` + 작업 + 완료 기준 + **회신 규약 v2**:
   ① 착수 보고(로컬/백그라운드 구분 + 각 예상 시간) ② 로컬 완료 즉시 회신
   ③ 백그라운드는 **선언 예상 + 유예 15분** 초과 시 중간 보고(팀원이 wakeup으로 자가 감지)
   ④ 전체 완료 시 결과 요약 + 잔여 수치화. 지연 판정 기준은 고정 시간이 아니라 선언 기준
   (착수 보고 10분 무소식만 즉시 지연 신호) — 장시간 bg 작업(12h 등)에서 오탐 없음.
3. 발송 대장 보고(누구에게 무엇을 보냈는지 표) — 회신은 턴 경계에 도착, 통신 그룹으로 대시보드에도 표시.
전송 주체는 항상 리더 세션 자신 — 수집기·훅은 관여하지 않는다(관측면 무개입).

## verify
설치 후 스킬 핫로드 확인 + 자식 조회 경로(register.sh status) 동작 확인.
실전 분배·회신 왕복은 첫 실사용 시 검증하고 decisions에 기록(임의 세션에 테스트 메시지를 보내지 않는다).

## 되돌림
`eharness wire dispatch --uninstall` — 스킬 제거뿐(설정·상태 무변경).
